# Plan — week of Monday 31 August

From the 27 August R&D meeting. Standups start Monday, 10:00 ET. Onboarding
launches **September 4th at 2pm ET**, which is Thursday of this week.

## What the meeting settled

- **Underground artists only.** Big names are a non-goal for now.
- **Interview questions go in the chat**, not email. Pete: "if you're there
  already, just answer these questions while you're here."
- **Contribution mechanics are deferred.** Carl: nothing beyond links is needed
  at this stage. Artist-curated personas are the differentiator from zero-click.
- **Profile pages must be scrapable by bots.** Carl: heavy client-side
  JavaScript means bots cannot execute it, so there is nothing to scrape. CY's
  goal: "when people start asking questions, LLM will start referring to Music
  Nerd as their source."
- **A domain credibility list**, not just ranking. Carl: "a list somewhere the
  LLM can consult." CY: high signal like Pitchfork, low signal like indices and
  scrapers.
- **MNTv comes after profile claiming.** Not this week.

## What is broken

All three shipped to staging at 02:44 ET on the 27th and were live for ten
hours before the demo. They are not deploy lag; they do not work.

1. **The ask errored on "what has Pete Rango been up to lately."** The exact
   query flagged in the meeting as the test of whether sources get cited.
2. **No source pills.** Sources are computed, and `citable` numbers the vault,
   the statements, the collaborators and the self-credits. Nothing renders.
3. **No hyperlinks on "who are Pete's collaborators."** The mentions resolver
   returns credited collaborators; the component linkifies them. Neither
   appeared. That request was also slow enough to comment on.

The ask reads the caption credits now, so "should have tapped into my
Instagram" should already be true. It isn't, which means the context is being
built and then not used, or not built at all. That is one diagnosis, not three.

## This week

### 1 · Fix the ask — Monday

Highest priority because it is the demo's credibility and because it is three
symptoms of something I shipped claiming it worked.

Reproduce on `staging.musicnerd.xyz` with Pete's profile and the two queries
from the meeting. Check in order: does the endpoint return `sources` and
`mentions` at all; does the caption context reach the prompt; does the model
emit `[n]` markers; does the component receive and render them. The error is
first — a 500 on a normal question is worse than a missing pill.

**Done when** both meeting queries answer without error, cite Instagram
material, and render pills and links.

### 2 · Domain credibility list — Monday/Tuesday

Boom Play and Clubhouse, in the shape Carl and CY asked for: a list the judge
consults while deciding, not an ordering applied afterwards.

`sourceAuthority.ts` already tiers hosts but only sorts. Extend to three
levels — preferred, unknown, low-signal — feed the tier into
`judgeSourceRelevance` so a low-signal domain needs stronger evidence, and keep
the list editable in one place so adding a domain is a one-line change.

**It ranks and gates; it does not silently delete.** A low-signal source that
survives still reaches the artist, who decides. Ranking something out of
existence is how a real source gets lost.

**Done when** a fresh run on Pete Rango files no Boom Play and no Clubhouse,
and the benchmark still scores 10/12 with zero wrong.

### 3 · Bot scrapability — Tuesday/Wednesday

Start with the measurement, because it decides whether this is an afternoon or
a project: fetch an artist page the way a bot does, with JavaScript disabled,
and see what is actually in the HTML. Carl's point is that if the content is
client-rendered there is nothing to index.

Then: server-render the profile content that matters, publish the knowledge
base as a crawlable page, and add structured data so a crawler can tell what it
is looking at.

Pete's clarification: **the public knowledge base is for LLMs and search
engines.** Fans need a better surface than the edit view, and that is separate
work, not this week.

Not this week: making the MCP server public without an auth token. Carl said to
track it, not to do it.

**Done when** an artist page returns its substance in the initial HTML, and the
knowledge base is reachable and readable without a login.

### 4 · Launch readiness — Wednesday/Thursday

September 4th is a launch, not a demo. The job queue has never run with several
artists onboarding at once, and every failure we found last week was in that
seam.

Run a deliberate concurrency test: several artists enqueued together, several
pumps ticking, and check that no job is claimed twice, no cursor goes backwards
and nothing completes while unfinished. Then walk one artist end to end in a
browser, which has still never been done on this build.

**Done when** concurrent onboarding is observed working, or the failure is
known before the 4th rather than during it.
